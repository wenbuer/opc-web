OPC · 运行闭环

任务 → 角色 → 解释，转回任务

人只说「要什么」，剩下的交给一条能自己收口的链路。

1

任务

R0（人）· R1 老板助理
  • R0 用一句话下达「要什么」
  • R1 拆成 1~3 个能独立交付的子任务
  • 子任务进队列，按优先级决定谁先跑
2

角色

R2~R7 各司其职
  • 每个子任务派给一个角色，带角色卡 + 装配技能
  • 角色在项目内自己用工具干活，产出落到工作区
  • 有护栏：轮数 / 工具数 / token 超限即停
3

解释

R1 汇总 · R0 批阅
  • R1 把回报解释成你能一眼看懂的东西
  • 要拍板的整理成决策建议，讲清背景与取舍
  • 你的批注即新指令，归档后沉淀进知识库

上一轮的结论，就是下一轮的输入 —— 所以它会自己越用越准。
