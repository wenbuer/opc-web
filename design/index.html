设计说明

SPEC · 取舍 / 映射 / 服务端需补的能力

1. 相比 opc-web 砍了什么

  • 删 三列桌面布局与左侧 shelf —— 手机只有一列，靠返回栈分层。
  • 删 定时任务、Skill 导入、模型接入、Token 统计明细 —— 手机端不做重配置，仍回电脑改。
  • 删 全屏运行日志 —— 降级为聊天室内联的事件行 + 「看实时事件」抽屉。
  • 删 项目文件 / 知识库独立一级页 —— 变成消息流卡片 + 详情页，入口不占底栏。
  • 留 下达任务、拆解回报、裁决三键、组织状态、简报 —— 手机上真正会用到的就这五件。

2. 工作台为什么是聊天室

  • 下达 = 发消息；拆解 = R1 的回复；子任务 = 带编号的结构化气泡；事件流 = 行内系统消息。
  • 好处是手机端天然的一条时间轴，不用在四列看板间横滑；角色发言天然回答了「谁在干、干到哪」。
  • 消息气泡里保留三键：看实时事件 / 看产出 / 立即执行，把桌面端的能力挂到消息上。
  • 左滑消息可「引用重跑」，等价于桌面端的重试按钮。

3. 服务端要补的（opc-web 侧）

  • OPC_HOST=0.0.0.0 之外还要真做鉴权：默认 127.0.0.1 是当前唯一防线。
  • 新增配对接口：POST /api/pair（一次性配对码 -> 设备令牌）、GET /api/pair/qr（生成二维码）。
  • 新增白名单：opc-config.json 里存 mobile_devices[]（设备码 / 名称 / 签发时间 / 吊销位）。
  • 设置页新增「移动端接入」子页（同现有 settings-nav 的第 8 项），展示二维码 + 已配对设备列表。
  • 移动端只需现有读接口 + 4 个写接口：/api/dispatch、/api/piyue、/api/plan-pause、/api/run/events。

4. 视觉规则（照 Material 3 落地）

  • 主色取 opc-web 的金 #e8b73d 做种子色生成色板；语义色沿用红（待裁决）/ 靛（角色）/ 绿（完成）。
  • 层级用 surfaceContainer 五档而非阴影；卡片圆角 18dp，主按钮与芯片用胶囊。
  • 标题 21sp / 正文 13sp / 元信息 11sp（等宽字体）；三个层级拉开，不用同一字号刷满全屏。
  • FAB 用圆角方块（不用圆形），只在工作台出现；底栏激活态是胶囊背景 + 图标变色 + 标签变 onSurface。
  • 全员无 emoji，图标一律 inline SVG（本页所有图标均为内联矢量）。

5. 页面与数据契约

屏数据来源关键交互
01 扫码配对QR: opc://pair?h=&p=&c=扫到 -> 校验配对码 -> 换设备令牌 -> 写入白名单 -> 跳 03
02 手动接入GET /api/ping + POST /api/pair三项预检；失败给明确原因（不在同网段 / 端口不通 / 未放行）
04 总览/api/home-stats /api/queue /api/run/events下拉刷新；点组织卡片看角色卡；点事件跳工作台对应消息
05 工作台/api/queue /api/plan-rows /api/run/events(SSE)发消息 = POST /api/dispatch；聊天流由任务 + 子任务 + 事件三源合并
06 批阅台/api/pending /api/task-output批准 / 驳回 / 修改 -> POST /api/piyue，批准即生成执行任务
07 消息/api/daily /api/ws-files /api/kb-entries分类筛选；产出预览走 /api/md，HTML 走 /api/ws-html
08 我的/api/settings /api/projects运行开关写回服务端；解除配对 = 吊销本机令牌
